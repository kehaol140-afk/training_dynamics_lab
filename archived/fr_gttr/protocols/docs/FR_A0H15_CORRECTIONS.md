# FR A0H-1.5 对 A0H-1 已交付结论的修正记录

日期：2026-09-14，与 docs/FR_A0H15_PROTOCOL.md 同日冻结（先于任何 A0H-1.5 结果）。
原则：保留原文与历史数字不删改；每条修正注明**依据**；原 FAIL 判定不变。

## 1. "逐元 gate 在 H≥4 对任何伴随不可满足" —— 过度推断，收窄为范围化观察

**原表述（A0H-1 handoff §3.2 / protocol §6）**：
"bf16 逐元 gate 在 H≥4 对任何伴随都不可满足……前向自身噪声地板已超过容差 ⇒
无论伴随如何实现，H≥4 逐元比较必失败。"

**修正**：该推断只覆盖**代数伴随**（把冻结算子每步转置拼接）这一类实现。
`forward_BF16 vs forward_FP32 > tol` 只说明这一比较超出原始容差，
**不能**推出"任何 BF16 伴随都不可能通过"。A0H-1.5 的 VJP 封装伴随
（对切线输入封装、锚点取 VJP）是**此前未测过的不同构造**，其对原始 gate
的满足性必须实测（A0H-1.5 §5/§6 Branch A），不得先验否定。

**依据**：浮点算子的转置伴随与微分规则 VJP 是不同对象；封装-锚点-VJP 路径的
误差结构（锚点处一阶项+实现一致性）不同于逐次代理转置的累积结构。
"不可满足"若要成立，需对所有可能伴随构造证明，A0H-1 只证了其中一类。

**保留的原始数字**（不变）：冻结 BF16 前向对自身 FP32-HVP 参照 max|Δĥ|：
H=4 1.43e-5、H=8 5.78e-5；BF16 代理自伴缺陷 2.4e-4..7.3e-2；伴随实现自身精确
（FP32-HVP 探针 4.1e-10）。这些是 A0H-1 的有效测量。

**新观察口径**：改用**重复运行**分离确定性偏差与随机变化（A0H-1.5 §4 REP）；
"噪声地板"改称"冻结 BF16 math-SDPA HVP 代理在给定方向上的方法间不一致性
（自伴缺陷）的实测量级"，注明其随方向与运行变化。

## 2. "K 的转置不存在/自伴不成立 ⇒ 无法定义共享伴随" —— 概念错误，更正

**原表述倾向**：以 `<Kx,y> ≠ <x,Ky>`（BF16 代理）作为伴随无法逐元满足的证据。

**修正**：浮点映射一般既不自伴也无精确转置伴随；`<Kx,y>≠<x,Ky>` **不能**
推出"K 的独立转置不存在"。正确对象是**锚点微分规则** DK(anchor)ᵀ，
由对切线输入封装后的 autodiff VJP 给出。共享伴随的可行性问题是
**实现/构造**问题（A0H-1.5 §5），不是存在性问题。

**依据**：VJP_K(anchor,y) 是 DK(anchor)ᵀ y；对封装器在锚点取 VJP 的复合
（G_0 转置 → A_kᵀ 链）给出的是**锚点处精确的一阶转置**（CPU FD 已证 1e-6），
其浮点残差与代理-自伴残差是不同量。

## 3. 双参照准则降为辅助，禁止作唯一标准；禁止追认 BF16 同配置等价

**原表述（A0H-1 handoff §6 A0H-2 候选）**：以
`|ĥ_adj − r32_j| ≤ |ĥ_frozen − r32_j| + tol`（r32=FP32-HVP 参照）作为等价准则。

**修正**：该比较**只作辅助报告**，不得作为唯一/主要通过标准；A0H-2 的
正式判据为 A0H-1.5 §6 Branch A/B 的决策级与（同配置）逐元标准。
**不得**据此或任何新证据把 A0H-1 的 BF16 逐元 FAIL 改判/追认为 PASS。

**依据**：双参照式允许"伴随与冻结前向同样差"通过，不能证明共享伴随保持了
冻结前向的决策输出；且 r32 本身是第三种配置，三角比较不构成同配置等价。

## 4. "no-op 恒 0" —— 消歧

**原表述**：no-op（a_0=0）分数恒 0，作为 no-op 一致的证据。

**修正**：拆为四个独立量，分别报告、分别核对：
- `noop_score`：no-op 候选的**得分**（定义上 ĥ_0 = w_0ᵀ·0 = 0；伴随侧同理）；
- `chosen_id`：argmin 选中的候选 id（含 0=no-op）；
- `choose_noop`：是否选中 no-op（bool）；
- `best_active_score` 与 `margin`：最优活跃候选得分及其与次优的间隔。
得分恰为 0 ≠ 选择 no-op ≠ 拒绝边界（"分数<0 才接受动作"）被检验过；
无 oracle-noop 回放样本时，拒绝边界一律记 **NOT_COVERED**，不宣称已验证。

**依据**：A0H-1 的 no-op 一致性只核对了 noop_score 与 chosen_id；
margin 与拒绝边界未核。
