# GTTR/F0 理论递推的独立 CPU 参考校验

本附件在本次回答中实际运行，仅校验 F0 的规则导数、clipping JVP、AdamW 全状态灵敏度与终点链式求导。它不是远程 Transformer、修复版生产代码、CAL-FIX 实验或训练收益的复现。

## 独立性与对象

- CPU，float64；4 个参数、两个参数块的光滑耦合 logistic loss。
- 明确的解析训练梯度和 Hessian驱动手写前向灵敏度。
- 独立写出的全展开可微 optimizer 轨迹通过反向自动微分计算规则梯度。
- 对真实合成终点目标另做两尺度中心差分。
- 原始 moments 非零，n0=46、beta1=0.9、beta2=0.999，保留偏差校正、当前v反馈、全局clip及解耦weight decay。
- schedule 总时钟始终256，读取h16/32/256，三种clip阈值，共九组条件。
- 每次步长/梯度/有限差分试验使用同一批预先生成的合成数据；不使用用户数据和检查点。
- 单独加入g=(3,4)、h=(4,-3)跨块裁剪反例，错误逐块dot必须被拒绝。

## 本次结果

结果见 independent_cpu_checks.json。九组前向灵敏度与完整反向求导的最大绝对差为4.163336342344337e-17；与所规定小尺度差分的最大绝对差为1.3567583471638112e-11。逐块错误clip JVP反例相对误差约0.48。

这些结果支持：在本校验的光滑/非分支边界条件下，F0声明的链式求导骨架可以正确实现，256步长度本身不使该公式失效。

它们不支持：原Transformer全程SENS已经正确；真实目标在delta=0.005/0.01的有限邻域近似线性；GTTR持续规则已有质量或token效率收益；已排除所有数值或实现问题。

## 运行

已有PyTorch的CPU环境执行：

```bash
python verify_reference.py
```

不需要GPU、不访问网络、不调用远程仓库、不修改原实验。所有数值仅为诊断参考，不得并入用户的原F0科学样本或训练预算。
